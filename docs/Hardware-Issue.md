> 작성일: 2026-07-26
> 범위: 전원 On/Off 스위칭 회로 설계, Arduino Uno 핀맵, I2C/SPI 부품 배치

## 1. Arduino Uno 핀 배치

### 문제
- Arduino Mega에서 Uno로 교체하며 인터럽트 핀이 6개→2개(D2, D3)로 줄어듦
- 좌/우 모터 엔코더 각각 A/B 2상씩, 총 4개 신호가 필요한데 인터럽트 핀은 2개뿐
- DS3120 서보는 25kg·cm 고토크로 stall 시 2~3A까지 소모 → Arduino 5V 핀으로 직접 구동 불가

### 해결방안
- 엔코더: **A상만 하드웨어 인터럽트**로 감시, ISR 안에서 그 순간 B상을 읽어 방향 판별 (해상도는 정석 쿼드러처의 1/4이지만 목표 위치오차(±20~30cm) 대비 충분하다고 판단)
- 서보: Signal 핀만 Arduino에서 받고, 전원은 모터 배터리 계열에서 별도 레귤레이터를 거쳐 공급 (Arduino와는 GND만 공유)
- Arduino 자체 전원은 배터리 직결(VIN) 대신 **RPi5에서 USB 케이블로 전원+통신 동시 수급**

### 실행 (확정 핀맵)

| 기능 | 핀 | 타입 | 비고 |
|---|---|---|---|
| Motor PWM (좌) | D5 | PWM(`~`) | 속도 제어 |
| Motor PWM (우) | D6 | PWM(`~`) | 속도 제어 |
| Motor DIR (좌) | D8 | 디지털 | 방향(HIGH/LOW) |
| Motor DIR (우) | D12 | 디지털 | 방향(HIGH/LOW) |
| Encoder A (좌) | D2 | 인터럽트 | RISING 시 ISR |
| Encoder B (좌) | D4 | 디지털 | ISR 안에서 읽기 |
| Encoder A (우) | D3 | 인터럽트 | RISING 시 ISR |
| Encoder B (우) | D7 | 디지털 | ISR 안에서 읽기 |
| Servo Signal (DS3120) | D9 | PWM(`~`) | Servo.h 라이브러리 |
| 전원 | USB (RPi5에서) | - | VIN 핀 미사용 |

## 2. Raspberry Pi 5 부품 배치

### 문제
- 원래 NFC(RC522)와 IMU(MPU6050)를 Arduino에 연결할 계획이었으나, Jetson Nano→RPi5 전환 및 역할 재조정 과정에서 위치를 다시 정해야 했음
- OLED(SSD1306) 추가 시 다른 I2C 장치와 버스 충돌 가능성 검토 필요

### 해결방안
- NFC 인증 처리와 EKF Sensor Fusion(IMU 포함)이 RPi5 담당 역할이므로, **RC522·MPU6050 모두 RPi5에 직결**하여 Arduino→RPi5 Serial 중계 단계를 없앰 (지연시간·Arduino 부담 감소)
- SSD1306은 MPU6050과 **같은 I2C 버스를 공유** — I2C는 주소로 장치를 구분하므로 SDA/SCL을 병렬로 그대로 연결하면 됨. 주소 충돌 여부만 확인(MPU6050 0x68 vs SSD1306 0x3C, 충돌 없음)

### 실행 (확정 배치)

| 부품 | 인터페이스 | 핀 |
|---|---|---|
| RC522 (NFC) | SPI0 | MOSI(19), MISO(21), SCLK(23), CE0(24), RST(임의 GPIO) |
| MPU6050 (IMU) | I2C1 | SDA(3), SCL(5), AD0=GND(주소 0x68) |
| SSD1306 (OLED) | I2C1 (공유) | SDA(3), SCL(5), 주소 0x3C |
| LiDAR X4 Pro | USB | 어댑터보드 경유 온보드 USB 직결, 별도 배선 없음 |
| UWB (Arduino Stella) | 확인 필요 | - |

## 3. 전원 스위칭 회로

### 문제
- 배터리를 모터 계열(22.2V)과 보드 계열(14.8V) 2개로 분리 운용하기로 함 (노이즈 격리 목적)
- 스위치를 2개 따로 조작해야 해서 사용성이 떨어짐 → 스위치 하나로 통합 필요
- 모터 정격전류(2~3.2A × 2 = 최대 6.4A) 자체는 DC 정격이 맞는 소형 스위치로도 직결 가능한 수준이지만, **비상정지처럼 모터가 실제로 전류를 끌어쓰는 도중(부하 상태)에 스위치를 조작해야 하는 상황("hot switching")**에서는 스위치 접점에 아크가 발생해 마모·고장으로 이어질 수 있음
  - 참고: 정지된 상태에서만 스위치를 켜고 끈다면("cold switching") 소형 스위치 직결로도 충분함. MOSFET을 추가한 이유는 정격전류 자체가 커서가 아니라, 부하 상태에서의 스위치 조작(비상정지 등)에 대비하기 위함

### 해결방안
- **DPST(2극) 스위치**로 두 배터리 계열을 한 번의 조작으로 동시에 On/Off
  - 극1: 보드 계열(14.8V, 저전류) → 직결 스위칭
  - 극2: 모터 계열(22.2V, 고전류) → 직접 끊지 않고 **P-MOSFET을 스위칭**하는 저전류 제어 신호로만 사용
- P-MOSFET Gate에는 오프 상태를 기본 유지하는 풀업 저항과, 배터리 완충 시(22.2V) MOSFET Vgs 절대정격(±20V)을 넘지 않도록 **제너다이오드 보호 회로** 추가

### 실행 (확정 부품/스펙)

**회로 구조**
<img width="1203" height="547" alt="image" src="https://github.com/user-attachments/assets/326dd433-7736-42b1-ad8e-839289b9ca6b" />

| 부품 | 스펙 | 선정 근거 |
|---|---|---|
| Q1 (P-MOSFET) | IRF4905 (Vds -55V, Id -74A, Rds(on) 0.02Ω, TO-220) | 완충 25.2V·순간 15~20A 대비 2배 이상 마진 |
| D1 (제너다이오드) | 1N4740A (10V, 1W) | IRF4905 Rds(on) 스펙 측정 조건(-10V)과 일치, 완충 시에도 Vgs 절대정격(±20V) 안으로 클램프 |
| R1 | 10kΩ, 1/4W | Gate 풀업 (평상시 OFF 유지) |
| R2 | 1kΩ, 1/4W | 스위치 ON 시 Gate 방전 전류 제한 |
| SW3 | KCD1-A 계열, DPST | 양쪽 극 모두 ≤1.5A만 담당하므로 소형 스위치로 충분 |
| F1, F2 | 퓨즈 (모터측 35A / 보드측 별도) | 각 배터리 + 라인 개별 삽입, 단락 시 화재 방지 |

**검증된 계산**
- 제너 클램프 시 Vgs ≈ -10V → IRF4905 완전 도통(Rds(on) 최소값 근처)
- 정상 주행(6.4A) 시 MOSFET 전압강하 ≈ 0.13V, 손실 ≈ 0.82W → 소형 방열판으로 충분
- 제너다이오드 소비전력 ≈ 12mW (정격 1W 대비 여유 충분)

**⚠️ 조립 시 확인사항**
- D1 방향: **캐소드(띠)가 BT+ 쪽, 애노드가 Gate 쪽** — 반대 연결 시 보호기능 무효화
- D1은 R1과 **병렬**로 Gate-Source 사이에 위치 (전원 전류 경로에 직렬 삽입 금지)
- 이 회로는 전압강하/전류제한용이 아닌 순수 On/Off 스위치 — 실제 모터 속도 제어는 MD20A의 PWM(Arduino 담당)이 별도 수행

## 4. 모터 회전 방향

### 문제

Arduino Uno에 전진(forward) 코드를 업로드했으나, 카트가 전진하지 않고 제자리에서 회전함.

### 원인

좌우 모터가 섀시에 서로 마주보는 방향으로 장착되어 있어, 두 모터에 동일한 방향의 회전 명령을 주면 실제로는 좌우 바퀴가 서로 반대 방향으로 굴러가게 됨 → 전진 대신 제자리 회전이 발생.

### 조치 사항

오른쪽 모터 드라이버의 출력 배선을 교체함.

| 모터 드라이버 출력 | 변경 전 | 변경 후 |
|---|---|---|
| MA | M+ | M- |
| MB | M- | M+ |

(왼쪽 모터 드라이버는 배선 변경 없음)

### 결과

좌우 모터 배선 교체 반영 후, 동일한 방향 명령에서 두 바퀴가 같은 방향으로 회전 → 전진 정상 동작.

### 확인 필요 사항

- [x] 후진 방향 정상 동작 확인
- [x] 좌회전/우회전(양쪽 모터 반대 회전 제어) 시 의도한 방향대로 도는지 확인
- [x] 배선 변경 사항 KiCad 회로도 / BOM에 반영

### 참고

배선을 바꾸는 대신, 소프트웨어에서 한쪽 모터의 PWM/DIR 신호만 반전시키는 방법으로도 동일하게 해결 가능. 이번에는 배선단에서 처리함.

## 5. 모터 소음 저감

### 문제
- 42-775B 유성기어 모터 구동 시 소음이 커서 저감이 필요함
- 서보모터(DS3120)를 최종적으로 사용하지 않기로 하면서 D9(Timer1)가 비게 됨 — 이 여유를 활용 가능
- 소음 원인이 하나가 아니라 여러 소스가 섞여있어 원인별 구분 필요:
  - 전자적 소음: PWM 스위칭 주파수(D5/D6 기본 980Hz)가 가청 대역이라 코일 진동음 발생
  - 기계적 소음: 유성기어 감속기 자체의 마찰/백래시음 (전기 신호와 무관)
  - 진동 전달: 모터 진동이 카트 프레임을 타고 공진·증폭

### 해결방안
- **전자적 소음**: 모터 PWM을 D5/D6(Timer0)에서 **D9/D10(Timer1)으로 이전**하고, 레지스터를 직접 조작해 PWM 주파수를 가청 영역 밖(20kHz)으로 올림
  - Timer0은 `millis()`/`delay()` 등 Arduino 기본 시간함수가 점유 중이라 절대 재설정 불가
  - Timer1은 서보 제거 후 미사용 상태이며 16비트라 20kHz 고주파 설정에도 유리해 이전 대상으로 선정

### 실행

**물리적 핀 변경 후PWM 20kHz 재설정 (D9/D10, Timer1)**

**변경된 최종 Arduino 핀맵** (서보 제거 반영)

| 기능 | 핀 | 비고 |
|---|---|---|
| Motor PWM (좌) | **D9** | Timer1, 20kHz로 재설정 |
| Motor PWM (우) | **D10** | Timer1, 20kHz로 재설정 |
| Motor DIR (좌) | D8 | 변경 없음 |
| Motor DIR (우) | D12 | 변경 없음 |
| (여유) | D5, D6 | 서보/모터 이전으로 비워짐 |

## 6. IMU와 디스플레이 신호 충돌 문제

### 문제 요약
RPi5의 동일 I2C 버스(Pin3 SDA / Pin5 SCL)에 MPU6050(IMU)과 SSD1306(OLED)을 함께 연결했을 때, OLED가 `i2cdetect`에서 전혀 감지되지 않았고, 이후 배선 개선 후 통신 자체는 성공했지만 실행 중 IMU 연결이 간헐적으로 끊기는 문제가 발생함. 최종적으로 OLED 통합을 포기하고 상태 표시를 LED 3색으로 대체함.

### 환경
- Raspberry Pi 5 (I2C1, GPIO2/GPIO3 = Pin3/Pin5)
- MPU6050 (GY-521 브레이크아웃)
- SSD1306 OLED (I2C, 128x64)

### 재현 순서 / 증상
1. MPU6050, SSD1306을 같은 SDA/SCL 라인에 병렬로 연결
2. `sudo i2cdetect -y 1` 실행 → `0x68`(IMU)만 감지, `0x3C`/`0x3D`(OLED) 미감지
3. 전원(VCC/GND), SDA/SCL 배선, SDA-SCL 스왑까지 확인했으나 OLED 미감지 지속
4. 배선 길이를 짧게 줄인 후 → OLED 통신 자체는 성공
5. 그러나 실행 도중 IMU(0x68) 연결이 간헐적으로 끊기는 문제 발생

### 시도한 해결 방법
- [x] 전원(VCC/GND) 배선 확인 — 정상
- [x] SDA/SCL 배선 확인, 스왑 테스트 — 변화 없음
- [x] `i2c-13`, `i2c-14` 등 다른 I2C 버스 확인 — 무관한 버스로 확인, 원인 아님
- [x] 배선 길이 단축 — OLED 통신은 성공했으나 IMU 간헐적 끊김 발생

### 원인 추정 (미확정)
- 두 브레이크아웃 보드가 각자 자체 풀업 저항을 내장하고 있어, 병렬 연결 시 등가 풀업 저항값이 과도하게 낮아지며 버스 신호 무결성이 저하됐을 가능성
- 확정하려면 각 보드를 단독으로 연결해 개별 동작을 재검증하거나, 외부 풀업 없이/풀업 값 조정 후 재테스트 필요 (미완료)

### 최종 결정
OLED 통합을 보류하고, 상태 표시를 GPIO 직결 LED 3색으로 대체:

| 색상 | RPi5 GPIO 핀 | 의미 |
|---|---|---|
| 초록 | GPIO22 | 모터 구동 중 |
| 노랑 | GPIO27 | NFC 태그 후 시스템 로딩 → 대기 상태 |
| 빨강 | GPIO17 | 정지 상태 |

IMU(MPU6050)는 OLED 없이 단독으로는 정상 동작 확인됨.
